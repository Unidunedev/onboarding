Até agora, os programas seguiam sempre o mesmo caminho. Com **condicionais**, eles passam a decidir: "se isso, faça aquilo; senão, faça outra coisa".

## se / senão

```pseudo
leia nota
se nota >= 7 então
    escreva "Aprovado"
senão
    escreva "Reprovado"
fim-se
```

## Mais de dois caminhos: senão se

```pseudo
se nota >= 7 então
    escreva "Aprovado"
senão se nota >= 4 então
    escreva "Exame"
senão
    escreva "Reprovado"
fim-se
```

As condições são testadas **de cima para baixo**, e só o **primeiro** caminho verdadeiro é executado. Por isso a ordem importa: se você testasse `nota >= 4` primeiro, uma nota 9 cairia em "Exame"!

| Pseudocódigo | C e Java | Python |
| --- | --- | --- |
| `senão se` | `else if` | `elif` |

## Condições compostas

```pseudo
se idade >= 16 e idade < 18 então
    escreva "Voto opcional"
fim-se
```

Em C e Java: `if (idade >= 16 && idade < 18)`. Em Python: `if idade >= 16 and idade < 18:`, ou o atalho `if 16 <= idade < 18:`.

## Condicionais dentro de condicionais

Dá para colocar um `se` dentro do outro:

```pseudo
se temIngresso então
    se idade >= 14 então
        escreva "Pode entrar"
    senão
        escreva "Precisa de um responsável"
    fim-se
senão
    escreva "Compre um ingresso"
fim-se
```

Se ficar muito aninhado (um dentro do outro, dentro do outro...), costuma ser sinal de que dá para simplificar com `e` / `ou`.

## Erros clássicos

- Usar `=` no lugar de `==` para comparar.
- Esquecer a ordem no `senão se`.
- Em Python, esquecer os dois-pontos `:` ou errar a indentação.
- Esquecer as chaves em C e Java quando o bloco tem mais de uma linha.

## Teste os limites!

O lugar onde os erros se escondem é **na fronteira**. Se a regra é "a partir de 7", teste 6.9, **7** e 7.1. Se é "entre 16 e 18", teste 15, **16**, 17, **18** e 19. A maioria dos bugs de condicional é um `>` que deveria ser `>=`.

#include <stdio.h>

int main() {

    else if (n < 0) printf("negativo\n");

}
